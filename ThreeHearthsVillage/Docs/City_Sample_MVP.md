# 一座有生活原因的小城：可运行样板

本轮把“同一栋房子排在地块上”推进到一个有公共目标、职业差异与持久故事的小城样板。居民仍然从真实木材建家、领取工钱、购买食物；后续构件建造必须通过材料、资金、道路、地面及支撑检查。

## 启动

在项目目录运行 `./Start-CityDemo.ps1`，打开 UE 后进入 Play。默认使用独立的 `Saved/ThreeHearths/World/city-sample.json`，沿用城市验证账本和本机 Kimi 配置。`./Start-CityDemo.ps1 -LocalOnly` 仅使用本地生活规则。正常退出 UE 后，脚本关闭它自己启动的网关；既有网关不归脚本所有。

旧世界按原位置和布局版本读取，不强行把已存在的房子移到新城市。要从头观察新布局，应使用独立的新世界或游戏的重新开始功能。

## 城市与建筑

- 主堡、市场、公共取货点和作坊有固定公共空间；主街绕开工作站，住宅巷道有转折和闭合街区。主堡位于实测可建的 `(-1050,2200,8)`，入口连接主街。
- 六类初始建筑外观：窄面住宅、前店后宅、带棚作坊、仓库、旅店、小型堡宅。体量、层高、屋顶、门窗、棚与烟囱随用途及持久偏好变化。
- 初始房屋完工后的职业外观是表现层，沿用原来的起居房建造配方；外观的楼层不代表可进入的内部楼层或营业能力。
- 后续原生构件房有五类可执行平面：住宅、前店后宅、带院作坊、仓库、旅店。先建付得起的核心，再按方向增加独立入口的房间，上限六间。已有构件的位置、材料和身份不因扩建被重写。
- 石材、木板、房梁、屋瓦与工钱分别检查；资源不足先生产、领工资。每次初始方案只尝试五个局部位置，不无限搜索，也不借修改存档制造材料。

## 国王与绿化

国王的持续目标是用真实税收和工钱建设主堡、美化王国，同时面对宫廷野心与民众生产的冲突。公共工程共 44 个构件、13 个依赖阶段：先主堡，再门楼和围墙，再侧翼与花园。配方共消耗石材73、木板46、房梁40；采购及工资另走经济账本。同阶段可多人运料，入口容量最多三人，安装仍借用同一把实际存在的锤子。工程只保护剩余工资与采购所需税金，余款解除保护并记入已释放税金，防止普通生产因无钱发工钱而停摆。

新增橡树、白桦、果树、柏树、开花灌木、野花六类植物，36处环境组合避开道路与建筑。环境植物目前是装饰；公共花园构件属于付费工程，尚无季节、生长、修剪或收获系统。

## 每个人怎样调用 Kimi

每位居民有独立持久的 `InnerStory`、设计目标和建筑偏好。故事首次生成后保存，重启不会重新抽取；国王征税、底层生计与职业野心写入背景。孩子、骑士、皇城订单等愿望必须标成未发生的意向。

看图流程是：选择该居民自己的已建建筑 → UE 导出512像素实景PNG → 连同建筑身份、持久故事及可执行选项送到 Kimi → 回答区分“看见／未知／打算” → 原生校验 → 保存意见或进入世界需求队列。国王有公共主堡进度时看主堡。评估图片隐藏其他居民房屋，避免把邻居房子当作自己的；图片不是模型生成的效果图。

每人最多一个在途请求，全局最多十个。视觉请求不占有生活调度；手动暂停看图时只接收设计意见，不推进施工。过期图片、未提供的动作或缺少证据区分的回复不执行。

初始职业外观和公共主堡允许“接受当前状态／提交待审需求”；原生构件房额外允许三个扩建方向。待审需求不会凭文字变成新物品或新玩法。当前没有运行时自动让 Blender 或 Meshy 建模的执行器，也没有自动让 Luna 改代码并发布的权限通道。

## 当前边界

这是有限构件与规则驱动的城市样板。街区密度配置还没有完整驱动地价、共墙、邻屋收购和连续店面；多层外观还没有室内导航；主堡施工在入口交接材料，堡内没有完整可走空间。想进一步接近 DND 城市，下一步应围绕相邻商铺、街巷立面、院落及公共空间做密度与生活动线验收，再扩充经济和资产生成。

## 验证记录

实际运行、费用、冷启动与图片以同目录 `Validation/City_Sample_Acceptance.json` 为准。预算依据见 [Kimi_Budget.md](Kimi_Budget.md)。费用记录区分真实平台 usage 与原生成功采纳，不把请求已结算等同于设计已生效。

2026-09-07 实跑完成10栋初始住所、4个原生建筑方案（2／1／4／2间，144/144构件），以及44/44公共工程构件。46笔木板采购、44份构件工钱都有账目；一份实际陶瓦订单完成交货。最终原生56项通过（其中6项带测试世界警告），预算离线15项、视觉接口离线4项通过。

最后一轮Kimi看图10/10回复全部采纳，观察到2个真实请求并行，角色故事与施工状态在评估前后相同；加上前一轮十次探索，本轮累计20次已结算，按usage共0.242723元，在途预留为0。五条新增需求以原话保留，四条美术提议、一条住所改造能力提议，均待审，未自动生成模型。四个原生建筑获得扩建方向意向，国王接受当前主堡状态。

真实测试也测出性能边界：快照读取平均约143毫秒；一次“截取PNG、建立请求并保存”约2.25秒，网络请求本身可并行。这段截图／保存准备仍同步，需要后续拆成队列与异步落盘，不能把它描述为完全无停顿的观察系统。
