# Level0：艾恩葛朗特第一层

2026-09-08 最新方向。用户决定彻底转向 SAO 第一层，并明确选择“新建 SAO 世界，旧世界留档”。本文件取代旧的中央高地城堡、国王征税和围绕高台建城目标。Level0 是本项目代号；原作场景称艾恩葛朗特第一层。

## 资料基准

以原作/《Progressive》及动画为基准。官方《Progressive》[作品介绍](https://sao-p.net/aria/story-character/)明确从第一层展开；[动画第二话官方梗概](https://www.swordart-online.net/aincrad/story/?id=ep02)确立第一层迷宫、首领房间与攻略会议的故事背景。

地图地理目前主要依据[第一层资料与剧场版小地图整理](https://w.atwiki.jp/saop/pages/430.html)、[第一层资料汇总](https://swordartonline.fandom.com/wiki/1st_Floor_%28Aincrad%29)和[托尔巴纳资料](https://w.atwiki.jp/saop/pages/19.html)。这些是二手资料，附有小说/动画出处；其中的想象地图不是官方测绘图。公开资料能够支持区域相对关系，不能支持每栋房屋的精确坐标。

第一层是约 10 公里直径的圆形楼层。南端为起始之城，外围为草原；西北有霍伦卡及森林，东侧为湖区，往北进入遗迹与山地，经过托尔巴纳抵达北端迷宫。起始之城包含城墙、中央广场、转移门及黑铁宫。托尔巴纳有风车和攻略会议场所。

尺度资料存在差异：一些英文汇总将起始之城描述为占楼层较大面积，而日文《Progressive》资料列出约 1 公里直径的半圆城。当前采用后者作为可核对的城市尺寸，整层尺度保持 10 公里；不把矛盾数据同时当作精确事实。

游戏改编版、同人设定和其他楼层不作为本轮地理依据。未明确的街区边界、湖岸线、街道与具体建筑布局，均为服从上述地理关系的项目补全。

## 固定骨架与可迭代部分

| 区域 | 地理与用途 | 当前实现层级 |
| --- | --- | --- |
| 起始之城 | 南端半圆城墙、广场、生活街区与商店 | 原生 UE 城市体量样板 |
| 黑铁宫 | 起始之城内的重要地标 | 独立建筑体量；内部与生命之碑待实现 |
| 草原 | 出城后的低风险探索环境 | 地形与路线；怪物和战斗待实现 |
| 霍伦卡与西部森林 | 村落补给、森林探索及任务 | 区域、村落体量、林地；任务待实现 |
| 东侧湖区 | 东路探索环境 | 湖盆与水面示意；水体玩法待实现 |
| 遗迹及北部森林 | 向北部推进的地理过渡 | 地形、遗迹体量、路网 |
| 托尔巴纳 | 迷宫前的城镇、风车、会面场所 | 城镇及风车体量；会议和服务待实现 |
| 迷宫区 | 第一层北端、通向下一层 | 塔体和入口轮廓；房间、战斗、首领待实现 |

地理模型采用厘米，X 向东、Y 向北，中心为 (0,0)。渲染统一转换为 UE=(东,-北,上)，避免俯瞰图东西颠倒并匹配三角面朝向。区域与道路的稳定 ID 由 `HearthAincradFloorPlan` 定义。精确坐标是工程选择，不代表官方坐标。城镇的安全区目前仅为规划标记，尚未接入战斗保护规则。

初始城镇允许已有建筑作为世界起点；后续居民扩建仍应有产权、资金、材料、时间和验收。世界生成时的房屋体量不能冒充居民通过 AI 自主施工的成果。

## 新世界与居民

- 地图：`/Game/ThreeHearths/Maps/L_AincradLevel0`。
- 新存档：`Saved/ThreeHearths/AincradLevel0/world.json`，独立世界 ID。
- 旧档：`Saved/ThreeHearths/Archives/Medieval_20260908_81BDF793/`，原世界文件仍保留，校验摘要记录在验收中。
- 新建 13 位原创背景 NPC 档案，身份是 SAO 本地居民，不冒充原作具名人物，也不把他们误当成玩家。档案保存长期故事、个性、住所引用、Col 与需求值。住所引用目前只是预留 ID，尚未绑定场景建筑产权；居民档案尚未实例化为自主活动角色。
- 目前档案能力只有地图样板和持久身份；商店 AI、战斗、剑技、任务、转移等明确为未启用。无国王、皇家税款和旧城堡工程。
- `world.json` 校验失败时停止载入，不自动造一个新世界覆盖它。保存保留上一版备份，并拒绝把另一世界 ID 写到现有世界路径。

居民自主故事与长期迭代是本项目对 SAO 的扩展。既有世界观作为约束，不能声称这种开放式 NPC 自我开发机制已经是原作明确设定。原作剧情人物与事件后续应单独确定是否重现，不能随机替换他们的既定经历。

## 可执行迭代顺序

下一阶段具体执行以 [起始之城迭代执行计划](Starting_Town_Iteration_Plan.md) 为准：先完成同档迁移和三位居民的真实行动/个人视野，再沿一条样板街完善美术与需求兑现。下列为整层路线概览。

1. 地理骨架：先验收整层南北关系、起始之城比例、城门与外部道路，以及进入迷宫的路线。本轮体量样板已验收，接下来进入起始之城迭代。
2. 起始之城样板街：完成广场、钟楼/转移门外观、旅店、铁匠与道具店的一段可步行街道，统一成年人物尺度、门窗、屋檐、屋顶与树木风格。粗略体量必须替换成有正常接口、碰撞和可进入空间的构件。
3. 居民生活：让同一批 NPC 从旅店/家出发到店面工作，用自己的 FOV 看自己经营的场所；真实调用 Kimi，区分已知记忆、当前看见和未实现需求。
4. 首个闭环：玩家或居民遇到具体困难，提出有限需求；主持人检查设定与成本，暂停世界完成最小功能或资产，恢复原存档，观察实际使用结果。
5. 城外内容：草原采集/怪物、霍伦卡任务、森林与湖区，再到托尔巴纳和第一层迷宫。区域按需加载和更新，不能让所有 NPC 每帧向 API 请求整个世界。

API 模型升级只更换决策适配层。世界状态、角色 ID、事件、资产 ID、规则版本与迁移记录持续保存。持续迭代依赖每次有界的真实验收；不把无监督、无限运行或无限预算当作已实现能力。

## 启动

使用 `Tools/Run-AincradLevel0.ps1` 启动新地图。数字键 1–5 在整层、起始之城、广场、霍伦卡、托尔巴纳之间切换；WASD 移动、Q/E 升降、按住鼠标右键转向，Shift 加速。

本轮浏览器/截图只是检查地图的协调者视角，不是 NPC FOV。当前启动脚本明确关闭 API；首次居民行为接入后再以既有 Kimi 账本进行真实验收，不让旧社会代码在新设定中继续扣税或委托城堡。

本轮另以现有账本进行了两次独立的 Kimi 协调者看图验收，并落实黑铁宫的深色金属材质。实机图、地图分布图、旧档哈希、重启验证和测试结果见 [2026-09-08 验收记录](../Validation/Level0_2026-09-08/README.md)。
