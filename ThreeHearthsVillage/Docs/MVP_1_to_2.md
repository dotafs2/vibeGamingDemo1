# MVP 1 → 2：能共同创造设施的自主小镇

规划日期：2026-09-05；进展更新：2026-09-06。第 1 步已完成，其余步骤仍为待实施计划。“MeshAI”暂按 Meshy 理解；如用户指另一家服务，只替换生成适配器。

当前进展：已用 Blender 制作原创低多边形小屋，修正重复瓦片共享 UV，并完成本地 GLB 在 UE 5.8.2 编辑器中的导入、材质验证、碰撞、摆放和场景保存。资源见 `Art/HearthCottage/README.md`。当前房屋制作不依赖 Meshy API。

第 1 步已通过本机 UE 5.8.1 编译、12 项离线测试、5 项原生测试和 11 项 PIE 验收，见 [PIE 导入预览与实拍](PIE_Import_Preview.md)。已验证材质、摆放、失败回退、等待期间模拟推进和退出清理；导入依赖独立编辑器工作进程。下一轮为第 2 步，稳定对象 ID 与静止世界存档。

2026-09-06 用户新增美术支线：模块化住宅、可选择墙材/屋瓦与 NPC 材料包。对应模型、装配和离线施工数据见 [模块住宅](Modular_Housing.md)。公共长桌/长凳同时补充会客点素材；世界存档、实时施工执行及导航的原有前置步骤仍未完成。

## 第一版可玩的目标

保留现有三名村民、岛屿和每人独立 AI。玩家只给一次共同目标：“建设一个大家愿意使用的公共会客点。”村民能吃饭、休息、选择个人活动、认领建设工作；其中一人提出公共长桌的外观描述，系统调用 Meshy 生成静态模型，自动接入 UE；村民完成材料与施工后，至少两人自发到场交流。关闭、重新启动之后世界和任务能恢复。

首版交付范围为 UE 5.8.2 编辑器 PIE 中的可玩演示，一种生成设施类型、一个生成任务并发。独立打包程序的运行时导入另设验收，不能用编辑器导入成功代替。生成物先采用静态公共长桌；村民可以围桌站立交流，沿用已有角色动画。

“自由生活”落实为每人有自己的需求、偏好和持续目标，并能在生活与公共工作之间选择。公共目标不替代个人 AI；规则层负责预算、材料预留、占地和实际效果。

## 当前 Demo 的缺口

- 已有执行能力：独立模型请求、13类生产建设操作、材料账目、运输、避让、休息和单人拜访记录。
- 缺少持续世界：只有角色历史，没有世界读档与任务恢复。
- 缺少真实需求约束：没有日常进食，低精力也可能继续重劳动。真实记录中出现粮食堆积和精力接近零仍建造。
- 缺少持续计划与协作意图：目前每次选择一个动作，模型只带本人最近三条完成记录；111次实测中15次目标变化后采用备用规则。
- 缺少双向交互：单人到达邻居位置不等于双方实际交流。
- 缺少完整造物链：没有模型生成任务、下载缓存、UE导入、功能模板、生成预算和自动放置。

## 每一行是一轮独立 AI 实现任务

按顺序交付，每轮都要求代码、可运行演示和对应验收；不把多行合并成一次“大改小镇”。规模过大时以验收边界继续拆分。

| 次序 | 本轮只实现什么 | 完成标准 |
| --- | --- | --- |
| 1（已完成） | 本地 GLB 异步导入验证 | 使用一份已知小模型，在 PIE 中加载、显示材质和摆放；失败时回到占位模型，游戏仍能响应。记录导入耗时和是否依赖编辑器。暂不调用 Meshy。 |
| 2 | 稳定对象 ID 与静止世界存档 | 给村民、地块、设施分配持久 ID；保存版本、位置、库存、需求、作物状态和模拟时间。空闲时保存、重开、加载，状态逐项一致。 |
| 3 | 自动存档与进行中任务恢复 | 保存携带物、已扣材料、目标预留、工作阶段和操作标识。运输/施工时中断再读档，不重复扣材料或入库；损坏存档可回退备份。旧 HTTP 回调失效，未确认请求不得直接重发。 |
| 4 | 饥饿与吃饭 | 增加饥饿和吃饭动作，按模拟时间变化；食物被真实消耗，吃饭后恢复。库存不足时产生补粮需求；暂停冻结需求变化。游戏日长度可配置。 |
| 5 | 精力约束和连续休息 | 按工作与返程预计消耗筛选动作，精力不足时优先休息；休息可持续到目标水平。村民不能靠精力为零无限劳动。 |
| 6 | 每人一个持续计划 | 增加个人目标、进度和重规划原因，例如“运回12份木材”。可连续完成两趟运输，不必每趟问模型；目标完成或条件改变后才重规划，计划可读档。 |
| 7 | 一种共同目标 | 加入“建设公共会客点”的目标记录、资源需求和完成条件，并提供简单面板。达到材料数量不算完成，设施可用并被实际使用才完成。 |
| 8 | 公共任务认领和意图共享 | 从目标产生采集、运输和施工工作。村民独立选择认领，规则层原子预留；其他村民能看到谁在做什么和预计到货。资源与岗位不会重复承诺，休息/中断时有明确释放规则。 |
| 9 | 最小双向社交 | 支持邀请、接受/拒绝、会面和结束。两名村民同时参与才降低双方社交需求、记录共同事件；工作中的人可以拒绝，不能远程独自刷社交效果。 |
| 10 | 会客点功能模板 | 先用占位长桌，固定合法占地、简单碰撞、两个以上站位和互动效果。村民能建造并围桌交谈；这些功能由 UE 实现，不由生成的网格决定。 |
| 11 | Meshy 异步生成适配器 | 独立生成服务/模块提交 preview、等待成功、提交 refine、下载 GLB 和材质到本地缓存。保存远端任务 ID、阶段、错误和费用信息；用假接口覆盖超时、失败和重启恢复，再做一件真实资产验证。 |
| 12 | 村民提出受约束的造物方案 | 村民输出结构化提案：模板类型、用途、尺寸、风格和外观描述。UE 检查模板、地块、资源及独立生成预算，合格后自动提交；相同提案复用已有任务/资产，不能重复扣费。 |
| 13 | 生成模型自动接入建设流程 | 检查文件、模型复杂度、材质数、尺寸和方向；沿用模板碰撞与站位。生成完成且施工完成后替换占位外观；失败保留占位设施，主模拟不等待生成服务。资产 ID 和本地缓存随世界恢复。 |
| 14 | 一次完整自主验收 | 玩家只给一次目标；村民维持生活、分工、生成并建成会客点、至少两人一起使用。连续跑3个游戏日，覆盖断网、生成失败和中途退出恢复，核对资源、模型费用和任务去重。 |

第1步是先排查技术风险；第2～10步使小镇具备生活与协作；第11～13步接通自主造物；第14步证明这条链真实成立。前一轮的验收失败时先解决，不在未完成的基础上继续堆功能。

## 生成与游戏的接口

```text
村民个人需求 + 小镇共同目标
    → 个人计划 / 认领工作
    → 造物提案（用途、功能模板、尺寸、外观）
    → 本地校验 + 生成预算 + 去重
    → Meshy preview → refine → 本地资产缓存
    → UE 异步导入 → 模板设施换装
    → 村民真实使用 → 共享事件与世界存档
```

设施的功能规则由程序控制：AI 可以选择受支持的用途、设计外观，Meshy 负责形状与贴图；一个外观看起来像工作台的模型不会自动具有生产能力。MVP只开放公共长桌模板，后续再逐项加入仓库、工坊和住房等模板。

AI 决策仍保持每名村民最多一个请求、每人至少6秒决策间隔和全村每轮600次上限。Meshy 费用另外计数：初始建议最多并发1件、每轮最多生成1件新设施；preview/refine分别记账。由运行者配置实际费用额度，使用已授权额度内的自动生成，无需让每个村民反复弹出确认。

预算不足、网络失败或生成排队期间，村民继续其他生活与工作。接口请求结果不确定时保留待核对状态，不能立即重新提交付费生成。优先轮询已持久化的任务 ID，下载完成后以本地资产与校验值恢复，不把临时下载网址当存档资产。

## 每轮交给 AI 的短任务模板

```text
实现 Docs/MVP_1_to_2.md 的第 N 步，只完成该行范围和验收。
先检查前置步骤与当前源码，复用现有执行、资源和历史系统。
保持每名村民独立 AI；不把新功能藏在提示词描述里，必须有真实游戏行为。
先使用本地/模拟数据验证；真实外部调用沿用当前明确授权和独立预算。
交付修改文件、可操作的演示方式、验证结果和未覆盖项；不要自动进入下一步。
```

## 已核对的技术依据

Meshy Text to 3D 提供 preview/refine 两阶段任务与状态查询，结果可选择 GLB。规划中的生成适配器据此设计，具体参数在实施时再次核对：[Meshy 官方 Text to 3D 文档](https://docs.meshy.ai/en/api/text-to-3d)。

UE Interchange 的导入路径和打包设置需要分别验证。第 1 步已在本机 UE 5.8.1 验证编辑器工作进程路径；打包运行时仍需独立验收。设计参考：[Epic 官方 Interchange 导入文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-assets-using-interchange-in-unreal-engine)。
