# 开发代理工作模板

以下是本轮实际分工及约束的可复用整理稿，不是完整逐字代理会话。模型、任务范围与当前验证结果见本轮交付报告；后续按用户最新授权调整。

## 主代理

先检查当前原档和已有真实 Kimi 证据，选出阻断生活的一处最小缺口。为工程代理规定互不覆盖的文件范围与稳定接口，保留原身份、历史、财产及未完成工作。审查变更，统一负责 UE/Blender/构建操作，完成本地检查后回到真实引擎和 Kimi 验收。代码和工具问题自行修复，只有无法判断的世界语义才向用户澄清。不能用 API 次数、模型数量或资产量代表社会进展。

## Luna：步行与观察

在现有 SAO 样板街添加可步行第一人称模式。限定修改 `HearthAincradLevel.h/.cpp` 中 Explorer、取景与 HUD 部分；保留旧预览机位与截图入口。实现成人眼位、水平行走、墙体阻挡、地面处理和简短操作说明。不要修改世界身份、居民决策或存档初始化，不另起 UE/Blender/API，不创建下级代理；完成后交代文件与尚未验证部分。

## Luna：工具委托内核

在独立 `HearthAincradLife` 模块实现原档 `life.version=1` 扩展。初始资源写明开发者来源，按居民稳定 ID 绑定；职业只参与初始技能配置，不作为永久权限类型。模型从当前合法选项中选择提案、接受、拒绝、取消、递送、修理、取回和使用。

必须检查产权、保管人、余额、费用预留、材料、工序和距离；同一工具不能有两个活动合约。操作 ID 重放不得重复交付或结算，同一 ID 换人或换参数必须拒绝。失败不修改原状态。个人上下文只含本人资产、经历、收到的消息和自身关系判断。使用真实工程代码、原子存档和必要测试，不用模型文字宣布已完成。

父代理负责把内核接到实际路线、工具显示、工时、相机和请求入口；纯函数通过不等于 NPC 已经自主跑通。

## 路线评审：三个独立立场

分别从世界连续性、自主社会和 SAO 玩家体验提出独立方案；每方说明优先目标、最大跑偏、必须保留与可替换内容、可证伪实验以及方案弱点。完成首轮后交换另外两方实际观点，逐一反驳并说明修正，不能预先编造辩论结果或强求一致。

第二轮共同压力案例：新模型让人物全部趋同；两天没有建设需求；建筑者无资源却要求后台直接造好；软件回滚是否可以抹去合法历史；职业是固定人群还是可学习职责；拒绝成交时如何验收。

结论与仍有分歧的部分保存在[路线评审](../Design/Persistent_World_Route_Review_2026-09-08.md)。

## 所有工程任务的执行边界

只做明确授权的任务；检索限定到相关文件、模块和类型，排除缓存与构建产物。共享编辑器和构建保持单一负责人。任务完成后关闭代理和自己启动的进程。世界动作、人工测试、本地回退和真实 Kimi 请求分别标注；重试不能绕过现实时间冷却、费用账本、安装去重或世界版本检查。
