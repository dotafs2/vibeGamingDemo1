## Project and construction

FHearthPublicProject refers to one Empty expansion ProductionSites index, Owner=-1, no cottage build plan. Approval expands site Radius to 350, recomputes approach and validates routes before commit. Public project blocks ordinary production at this site. ApprovePublicProject requires an idle king and immutable 25% policy, creates GUID project/approval IDs and matching local king history (kind public_project_policy, Context includes ApprovalHistoryId). Status unapproved / building / completed. No approval on three-resident test map. Scheduler AdvancePublicWorks runs before resident tasks each simulation tick, throttles assignments to one simulated second, only with autonomy enabled, avoids pending API/social tasks. Public construction does not depend on cloud availability.

HearthPublicWorks::Populate creates 15 stable parts ordered foundations (3), stones (3), walkways (3), parapets (6): bay X=-200,0,200; foundation Z=0 recipe[4,0,0]; stone Z=28 recipe[8,0,0]; walkway Z=267.7 recipe[0,3,2]; parapets Y=+/-38 Z=289.7 recipe[0,2,1]. Asset ids are public_wall_{foundation,stone,walkway,parapet}_2m. Stable Id=Project.Id + ':' + descriptive bay/component suffix. Stages1..4. Required arrays are stone/planks/beams. Total36/21/12.

Project Stock comes from actual public stone/beam grants (deduct global depot and increment Grants[0/2], Grants[1]=0), or completed resident plank purchases. Public allocations are explicitly labelled grants, not sales. Grant lineage is project ID plus aggregate source/material quantities; preserve quantity conservation. Construction is sequential first unfinished part, with only one assigned worker, statuses waiting / transporting / installing / completed. Reserve entire recipe in Part.Reserved, reserve tax-funded wage2 via ReserveWage, borrow hammer operation5. Part.TaskId=R.ActiveTaskId GUID. New PublicTravel/PublicWork tasks keep R.ProductionSite/Op=-1 and ProductionComponentId empty; R.CargoType2/3/4 and Amount<=6 transfer reserved -> cargo -> delivered. PublicTravel covers depot/site round trips, timer applies only PublicWork. Before completion SettleWage succeeds, then consume all delivered, add to global Spent[2], ManufacturedSpent[0/1], increment project.Completed, clear worker but retain part task ID matching paid tax wage. CancelPublicWork restores reserved+delivered+cargo to project stock, cancels wage/refunds protected money, returns tools, resets worker idle and part waiting. Completed parts cannot cancel.

## Procurement

HearthProcurement.cpp owns StartSupplyOrder, SettleSupplyOrder, CancelSupplyOrder, AdvanceSupplyWorker. Start requires approved incomplete project, idle resident (CanAssignActivity), PersonalPlanks>=1, unfilled project plank need, tax and treasury >=2, route to public depot (-1650,-1050,8). Reserve one privately owned plank (existing sawmill share or completed trade), deduct Treasury and TaxProject2, record order escrow2 and reservedQuantity1. Order GUID=resident ActiveTaskId, ProjectId=current project. Status transporting / completed / cancelled. Price2, Quantity1 immutable; Origin resident_owned_sawmill_share_or_completed_trade. Travel+handover uses new tasks; no R.Cargo (order carries reserved material), no borrowed tool. AdvanceSupplyWorker handles timeout with simulated Dt and travel, then 1 simulated second handover. Settle preflights tax and ledger capacity BEFORE any mutation, creates public_purchase transaction From=-1 To=seller Amount2 Item=plank Quantity1 TaskId=orderId, adds gross wallet2 then CommitIncomeTax, moves plank to projectStock[1], clears escrow/reservation, marks completed. Failure leaves everything unchanged for retry. Cancellation returns original plank and both cash balances exactly once, no sale. Completion/cancel clears ActiveTaskId/route, closes history and cooldown on simulation clock. Do not request API calls.
