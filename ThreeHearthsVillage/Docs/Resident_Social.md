# 居民之间的对话与承诺

居民先走到一位空闲邻居身边，双方当面轮流说中文。对方正在生产、建房或等待自己的模型回应时，拜访不能抢走其任务。只有实际说出并听到回应，双方的社交需要、心情和关系才会改变；旧版“走过去等计时器结束”不再直接提供社交奖励。

每轮回应由当前说话者独立决定，提供自己的身份、职业、人设、需要、对对方的记忆、已有对话和当前可执行提议。Kimi 继续经过同一持久化人民币预算网关，每人最多一个在途请求，全项目最多十个；没有新增直连付费接口。离线模式使用明确标注的本地规则，仍走同一套会面、轮流回应和执行状态。

## 行动结果

| 对话意图 | 实际行为 |
| --- | --- |
| 问候、回应 | 轮到另一位居民开口，关系分别记录 |
| 邀请吃饭 | 对方可以接受或拒绝；接受后两人各执行真实吃饭任务，每人实际吃到时扣一份食物 |
| 请求采集帮助 | 选择一个资源和路线可用的任务；对方接受后实际前往、采集、搬回并交付 |
| 拒绝 | 对方保留自己的安排，不强行派发任务 |
| 告别 | 结束当前对话，继续各自的生活决定 |

答应只创建承诺，不产生材料或信任奖励。采集必须扣减来源资源并送达公共库存，吃饭必须真正消耗库存，才会把承诺标记为已履行并提升受益者的信任。执行时资源已不可用会记录未履行并降低信任。同一个任务 ID 完成多次通知，也不能重复获得关系收益。

关系是有方向的：甲对乙与乙对甲分别保存好感、信任、见面次数和最近记忆。接受与拒绝并不强求双方心情完全一致。普通决定间隔约 6 秒模拟时间，已经进行的任务继续执行；会面后的新回应属于事件触发。对话显示、赴约和轮次等待也使用模拟时间，随倍速缩放并在暂停时冻结。

## 查看与恢复

选择居民后点击“对话与关系”，查看其记忆、承诺进度及双方说过的话。画面气泡标明当前说话者的名字。聊天正文是实际回应，不是模型内部思考。

世界存档 schema 3 保存双方稳定 ID、当前轮次、对话、关系、承诺、执行中的任务 ID 和话语剩余显示时间，并继续读取 schema 1、2。恢复途中对话或运输不会重复添加话语、承诺、见面次数、库存或信任。若退出时有未确认付费回应，世界保留记录，当前运行停止付费请求，不自动重试；费用仍由世界以外的固定账本管理。

这是问候、吃饭和采集帮助的闭环。货币交易、劳动订单、婚姻、生育和王位制度需要后续独立系统，当前对话不能凭空完成这些事情。附件、家具的原生美术导入也不表示交互与动画已经接入。

验收记录见 `Docs/Validation/Resident_Social_Acceptance.json`：10 项原生检查通过；实际岛屿离线五轮对话、真实木材交付、中途读档与去重通过。限定模型复验为 2 轮 Kimi 回应加 3 轮明确标注的本地回退，承诺最终完成并交付 6 份木材。

首次纯模型尝试中，第三句文字提出帮忙却选择闲聊，第四次模型接受不存在的提议被原生校验拒绝，没有派发无效工作。已补充住房事实、历史动作与文字必须匹配动作的约束；失败证据保留。完整纯模型多轮约定尚未验收，提示词改善不替代运行时校验。两次社交测试共 6 次实际请求，均有 usage 回执，累计 0.0420196 元。
