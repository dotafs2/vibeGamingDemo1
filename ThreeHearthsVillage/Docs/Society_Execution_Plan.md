## 1. 物品归属、领用、借还与转交

- 区分所有者、存放地点、当前持有人和预留任务。初始物资有明确来源账，工具实例具有持久 ID；已有地块产权保持不变。
- 公共库存、个人物品、在途货物之间实际转移；工具显示从真实持有状态派生，不能因为开始动作就凭空获得一把工具。
- 先完成一个借用工具、工作、归还或转交的真实场景。接受、拒绝、按时归还和失约接入既有对话、承诺、信任与记忆。
- 验收：多人争用最后一件工具、工作切换、中途读档、重复完成通知均不复制或丢失物品，不重复增加关系收益。旧存档迁移只执行一次。

## 2. 一条真正的加工链

- 先做木材到木板、房梁，不一次铺开所有配方。使用已有木工台、材料包、锯等资产；缺少的必要资产由 Blender 补齐。
- 加工消耗来源明确的原料、占用地点和工具、经历劳动时间，产物进入实际库存；角色需要能运输和交付。
- 至少两位居民承担不同环节并有可见交接。职业影响选择，但避免强制岗位让十人小村因缺一个职业永久停摆。
- 验收一份原料从采集、运输、加工到成品的完整去向；生产途中保存恢复不能重复扣料或重复出货。之后再扩展砖瓦、石灰和涂料。

## 3. 居民收入与实际交易

- 增加有来源账的初始货币、个人钱包、交易记录和最小买卖/劳动订单；先保证可运行，再扩展复杂议价。
- 对话中提出购买、出售或雇佣，对方能接受或拒绝。成交必须同时满足真实货物、资金和交付条件；不得只写一句成交文案。
- 交货与付款按稳定交易 ID 结算；物品和货币转移可追溯，钱不够或货不够时不得凭空补足。履约和失约影响信誉与后续选择。
- 验收两名 NPC 实际交换货物和钱，双方余额/库存对应变化；断档恢复、取消、失败和重复回调不重复付款。先形成能循环的简单市场，不预设复杂金融制度。

## 4. 从小组件真正建成房屋

- 读取现有 VillageKit 施工计划；先完成一种住宅，再推广三种布局及合法材质组合。
- 地基、楼板、柱梁、墙、屋顶由独立安装任务逐件生成。每一步绑定材料预留、搬运交付和施工结果，成品模型替换不能冒充模块执行器。
- 占地、门口路线、工作站位、碰撞和通行要在真实地图验证；施工中断后从原任务继续。
- 验收一栋住宅从空地到完整房屋的截图序列和材料账，至少一次施工中途读档。既有房屋与存档必须安全迁移。

## 5. 收税、国库与城堡工程

- 国王继续是有个人需要、记忆和关系的 NPC；个人钱包与国库分开。
- 税来自已经发生的应税收入或交易，税目与来源清晰，同一事件只收一次。国库采购真实建材并向居民支付劳动报酬。
- 先用现有城堡组件建出一座小塔或一段城墙，让税款、采购、运输、安装和工资形成循环，再逐步扩展城堡与下方街区。
- 验收税款没有凭空生成，工程花费能对应村民收入和材料消耗；资金短缺会影响工期与 NPC 选择，而不是直接刷出建筑。

## 6. 更丰富的关系与家庭

- 在前面各单元中持续加入可追溯的社交记忆和行为后果，避免先做大量只改变数值的情绪标签。
- 经济与居住稳定后，依次实现亲密关系、双方同意的婚姻、共同居住、孩子与抚养、成长和继承；每步都有资源、时间和存档支撑。
- 后续可扩展公共意见、冲突、失去支持和王位变化。不要用角色头衔或一段故事文本代替实际制度。
