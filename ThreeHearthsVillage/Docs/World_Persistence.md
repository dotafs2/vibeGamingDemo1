# 世界存档与任务恢复

世界现在拥有独立 ID；每位居民、住宅地块、生产地点和持续任务也有固定 ID。关闭播放再打开会恢复同一个世界，只有“重新开始”才建立新世界，并保留旧存档。此单元首先保障原有三居民运行；十居民和社会系统将使用后续版本迁移。

默认文件是 `Saved/ThreeHearths/World/current-world.json`，上一份完整文件是 `.bak`。每 30 秒真实时间自动保存，结束播放时保存；暂停时也可保存。Blueprint/Python 可调用 `SaveWorld`、`LoadWorld` 和只读 `ExportWorldState`。`GetSnapshot` 仍是诊断摘要，不能充当恢复存档。

保存内容包括：世界时间与速度、暂停状态、居民身份与人设、位置与路线、剩余计时、精力与社交需求、住宅产权与施工阶段、身上和已交付材料、生产地点预订与已预扣材料、在途产出、公共库存、资源来源和消耗累计、作物生长、任务历史。表现网格从逻辑状态重建。日常决定保存剩余等待时间，不保存另一进程无法使用的单调时钟绝对值。

保存先验证整个逻辑状态，将 UTF-8 文件完整写入并刷盘，然后在同一目录原子替换。文件带 SHA-1 校验和，用于识别截断或意外损坏，不作为防篡改签名。读取还检查版本、数值范围、ID 唯一性、产权与任务引用、材料守恒。当前版本要求食物初始30、木材36、石材0的来源账平衡。确认全部有效之后才替换运行中的状态。

Windows 同一路径的世界使用独占文件句柄，第二个编辑器/PIE实例会暂停，防止两个模拟同时修改世界。进程崩溃会由操作系统释放句柄；遗留的 `.lock` 文件不代表世界仍被锁定。自动保存拒绝覆盖损坏文件。读取主档失败时，保留原文件为带时间与 GUID 的 `.archive-*`，恢复上一份完整备份；两个文件都损坏则保留原件并暂停，不悄悄重建世界。

材料交付和任务阶段切换在同一个游戏线程步骤内完成。存档同时包含来源、身上材料、库存和所处阶段，因此重启后继续当前阶段，不再执行开工扣料。崩溃后最多回到上个30秒检查点；该时段全部内部世界状态一起回退，不会只回退库存或只回退搬运任务。不存在实时多人或外部交易结算接口。

付费请求在发送前保存操作 ID 和在途标记；存档失败会阻止发送。恢复时若发现未确认请求，不自动重新调用模型，本轮使用本地规则。外部人民币费用不随世界回退：独立预算账本仍保存已结算费用和所有不确定预留，居民请求头使用持久居民 ID。

测试可指定 `-HearthWorld=<isolated-file>` 和 `-HearthHistory=<isolated-history>`；纯隔离测试也可使用 `-HearthNoWorldPersistence`。测试必须显式使用关闭 API 的 `-HearthApiConfig`，不能通过世界文件改变预算目录或退款。

验收结果见 `Docs/Validation/World_Persistence_Acceptance.json`。当前尚不包含跨人口版本迁移、离线期间模拟推进或角色附件动画状态的恢复。
