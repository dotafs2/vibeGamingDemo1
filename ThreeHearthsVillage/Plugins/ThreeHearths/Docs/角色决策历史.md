# 角色决策历史与自主生活

点击场景中的小人或左侧姓名，右侧就会打开这个角色的全部抉择。最新在上，滚轮向下看旧记录；点击“查看当时状态与可选行动”展开选择前的精力、社交需求、人设和可选目标。每条记录会从“等待回复”更新为“执行中”，再变为“已完成”。中途重开或退出，未完成的决定标为“已中断”。

每条记录包含真实时间、游戏时间、轮次、选择、简短理由、执行结果、决策来源、接口耗时和模型报告的 Token。这里展示的是模型返回的角色理由，不是模型内部思考过程。接口失败会标明本地备用规则，错误原因保留在展开的详情中；本地选择不会假装成 Kimi 回复。

生产版已新增完整采集、农业和扩建任务，详见 [生产与建设技能](生产与建设技能.md)。这些操作也会保存完整历史，运输记录会区分携带中与入库；手动安排标为“你安排的任务”。

建完房后，角色会根据精力、社交需求、人设和近期经历继续安排生活：回家休息、拜访已有房屋的邻居、观察农田、巡查树林与木材站。休息恢复精力，拜访降低发起者的社交需求；观察暂不产生收获或改动库存。尚未实现双向对话。

选址和生活决策使用各自独立的请求，每名村民最多一个未完成请求，并发能力随村民数量变化，没有固定三人的总限制。当前有三名村民，因此可以同时发出三个请求。生活决策每人至少相隔 6 秒模拟时间，随倍速缩放并在暂停时停止，并且要完成当前活动后才会再选择；一个人的等待或超时不会挡住其他人。当前每轮最多 600 次模型请求，包含选址。达到上限后村民按本地规则继续；重新开始重置这轮调用计数。

这解释了旧版 Token 停住的原因：旧版每个人只调用一次模型选址，后续搬运与建造全在本机进行。现在新增活动会继续产生请求；移动每一步仍由 UE 执行。

并行回复由 UE 主线程逐个应用，并再次检查地块占用、当前材料和动作有效性。同一地块不会被重复预留，材料不足时不会重复扣款。冲突或无效回复会注明本地备用选择，Token、耗时和结果仍记在发起请求的角色名下。重新开始会取消全部旧请求，迟到的回复不会影响新一轮。

“自主：关”停止安排新的生活决定，正在执行的活动会完成。暂停停止模拟与新请求；已经发出的 HTTP 请求可能继续返回，决定会等待恢复后执行。倍速影响移动、建造、活动和下一次决策冷却；模型网络回复仍按实际时间等待。

配置项位于项目本机 `Saved/ThreeHearths/api-config.json`，更改后点“重新开始”生效：

| 配置项 | 当前配置 | 含义 |
| --- | --- | --- |
| `autonomous_life` | `true` | 是否继续安排生活 |
| `life_decision_interval_seconds` | `6` | 每名村民生活决策的模拟时间间隔，支持 1～120 秒；随倍速缩放，暂停时停止 |
| `max_requests_per_run` | `600` | 全村共享的本轮模型请求上限，支持 1～1000 |

完整历史保存在 `Saved/ThreeHearths/decision-history.json`，每次状态变化自动保存，重开保留。界面使用可滚动列表，不限制只看最近几条。模型上下文只携带本轮该角色最近三次已完成决定，避免每次重发全部档案。

启用此功能前只剩最后一轮快照，因此只恢复了那一轮三个角色的选址理由，标为“旧版恢复”，不补造历史时间或 Token。完整历史从新功能启用后开始记录。档案仅保存经历，不等于世界存档；重开仍会重置房屋和木材。

历史与状态快照不包含密钥。测试使用单独的 `-HearthHistory=` 和 `-HearthApiConfig=` 文件，测试记录不会混进真实角色档案。
